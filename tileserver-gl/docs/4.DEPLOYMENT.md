# Deployment

Typically, you should use nginx, lighttpd or apache on the frontend. The tileserver-gl server is hidden behind it in production deployment.

## Docker Compose

```yaml
services:
  tileserver-gl:
    container_name: tileserver-gl
    image: stsdockerhub/tileserver-gl:<ver>
    volumes:
      - "./data:/data"
    command: ["--config", "/data/config.json"]
    ports:
      - "8080:8080"
    restart: unless-stopped
```

Keep the container port at 8080: the bundled `HEALTHCHECK` probes `http://localhost:8080/health` inside the
container, so `--port` would make an otherwise healthy container report unhealthy. Map a different host port
instead. Swap the image for `stsdockerhub/tileserver-gl:<ver>-light` when no server-side rasterization
is needed — it is considerably smaller and does not need the GL stack.

`GET /health` returns `503 Starting` until all styles and data sources have finished loading, then `200 OK`.
Use it as the readiness probe behind a load balancer so the first requests do not hit a half-initialized server.

## URL generation behind a proxy

The server builds absolute URLs (TileJSON `tiles`, `styles.json`, WMTS capabilities) from the incoming
request. `trust proxy` is enabled, so these headers are honoured:

* `X-Forwarded-Host` — hostname
* `X-Forwarded-Proto` / `X-Forwarded-Protocol` — `http` or `https`
* `X-Forwarded-Port` — port
* `X-Forwarded-Path` — path prefix, for serving under a subpath

Because those headers are attacker-controllable when the proxy does not overwrite them, pick one of:

* `--public_url https://tiles.example.com/` — every generated URL uses this prefix and the headers are ignored.
* `allowedHosts` in the config (or `TILESERVER_GL_ALLOWED_HOSTS`) — a host allowlist. Requests arriving with
  any other host get relative URLs instead of the forged one.

If neither is set the server logs a host-header-poisoning warning at startup. Make sure the proxy sets the
forwarded headers itself rather than passing through client-supplied ones — with nginx, `include proxy_params`
(Debian/Ubuntu) does this.

## Nginx Cache

If you have a reverse proxy setup in front of the tileserver you may want to enable caching as it will greatly offload requests from the application.

Configure the proxy cache path directive to initialize your cache store:

```
  proxy_cache_path /var/cache/nginx/tileserver
                   keys_zone=TileserverCache:50m
                   levels=1:2
                   inactive=2w
                   max_size=10g;
```

Make sure to give proper permissions for the /var/cache/nginx/tileserver folder. Usually nginx is running with www-data user.
Enable caching on specific proxy pass:

```
  location / {
    include proxy_params; 
    proxy_pass http://127.0.0.1:8080/;

    proxy_cache TileserverCache;
    proxy_cache_valid 200 1w;

    # add_header X-Cache-Status $upstream_cache_status;
  }
```

If you need to confirm whether caching works or not, uncomment the X-Cache-Status header. 
This will return a header on response with `HIT` or `MISS` header value which indicates if nginx cached the response or not.

Make sure to clean your cache by removing files in the configured directory after you change your styles or tile information. 
You may experiment with the caching values to fit your needs.

More about Nginx caching: https://docs.nginx.com/nginx/admin-guide/content-cache/content-caching/

## Nginx Reverse Proxy

An example nginx reverse proxy server configuration for HTTPS connections. 
It enables caching, CORS

```
  proxy_cache_path /var/cache/nginx/tileserver
                   keys_zone=TileserverCache:50m 
                   levels=1:2
                   inactive=2w
                   max_size=1g;

  # No query string or Referer, so ?key= API keys and tokens never reach the log.
  log_format tileserver_noquery '$remote_addr [$time_local] '
                                '"$request_method $uri $server_protocol" '
                                '$status $body_bytes_sent $request_time '
                                '"$http_user_agent"';

  map_hash_bucket_size 128;
  map $http_origin $allow_origin {
      https://www.example.com $http_origin;
      default "";
  }

  server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;

    ssl_certificate         /etc/ssl/www.example.com/cert.pem;
    ssl_certificate_key     /etc/ssl/www.example.com/key.pem;

    server_name www.example.com example.com;

    access_log /var/log/nginx/tileserver.access.log tileserver_noquery;

    # Disable root application access. You may want to allow this in development.
    location ~ ^/$ {
      return 404;
    }

    # Disable root application access. You may want to allow this in development.
    location /favicon.ico {
      return 404;
    }

    location / {
      # This include directive sets up required headers for proxy and proxy cache.
      # As well it includes the required ``X-Forwarded-*`` headers for tileserver to properly generate tiles.
      include proxy_params;

      proxy_pass http://127.0.0.1:8080/;

      # Disable default CORS headers
      proxy_hide_header Access-Control-Allow-Origin;

      # Enable proxy cache
      proxy_cache TileserverCache;
      proxy_cache_valid 200 1w;

      # Set our custom CORS
      add_header 'Access-Control-Allow-Origin' $allow_origin;
      
      # If you need to see nginx cache status. Uncomment line below.
      # add_header X-Cache-Status $upstream_cache_status;
    }
  }
```

## Serving under a subpath

Two equivalent ways to serve the tile server at, say, `https://example.com/tiles/`:

* start it with `--public_url https://example.com/tiles/`, or
* have the proxy send `X-Forwarded-Path: /tiles` along with the other forwarded headers.

Both make the URLs inside `style.json`, TileJSON and WMTS documents point at the public location.

## Monitoring

Start the server with `--metrics` (or `TILESERVER_GL_METRICS=true`) to expose Prometheus metrics. The metrics
listener is a separate server bound to `127.0.0.1:9090` (`METRICS_PORT`) — it is intentionally not reachable
from outside the host, so a scrape from elsewhere needs a sidecar, a `network_mode: host` exporter or a proxy
that terminates the scrape locally. See [USAGE.md](2.USAGE.md#prometheus-metrics) for the metric list;
`tileserver_render_pool_waiting` and `tileserver_tile_render_duration_seconds` are the ones that tell you the
renderer pools are undersized.

## Resource tuning

* `minRendererPoolSizes` / `maxRendererPoolSizes` decide how many MapLibre GL Native renderers are kept per
  scale factor. Each renderer costs memory; too few means requests queue. Start from the defaults
  (`[8, 4, 2]` / `[16, 8, 4]`) and watch `tileserver_render_pool_waiting`.
* `UV_THREADPOOL_SIZE` defaults to `max(4, cpus × 1.5)`. It governs the threads available for SQLite and
  image encoding.
* The Docker images preload jemalloc (`LD_PRELOAD`, `MALLOC_CONF`) because glibc's allocator fragments badly
  under the renderer's allocation pattern. Keep it when deriving your own image.
* `tileMargin` improves label clipping at tile borders but multiplies the vector tiles fetched per rendered
  tile — measure before enabling it in production.
* Rendered tiles are expensive; a proxy cache in front (see above) matters more than any of these knobs.

## Updating the configuration without downtime

Send `SIGHUP` to reload `config.json` in place (`docker kill -s HUP tileserver-gl`). The process closes its
tile sources, clears the PMTiles cache and re-reads the config; concurrent reload requests are queued. With
`serveAllStyles` enabled, style files added or removed in `paths.styles` are picked up automatically.
