# Usage

## Getting started

```
  Usage: tileserver-gl [mbtiles] [options]

  Options:
    --file <file>             MBTiles or PMTiles file (local path, http(s)://, or s3:// URL)
                                ignored if the configuration file is also specified
    --mbtiles <file>          (DEPRECATED) MBTiles file
                                ignored if --file or the configuration file is also specified
    -c, --config <file>       Configuration file (default: "config.json")
    -b, --bind <address>      Bind address
    -p, --port <port>         Port (default: 8080)
    -C|--no-cors              Disable Cross-origin resource sharing headers
    -u|--public_url <url>     Enable exposing the server on subpaths, not necessarily the root of the domain
    -V, --verbose [level]     More verbose output (level 1-3)
                                -V, --verbose, -V 1: important operations
                                -V 2: detailed operations
                                -V 3: all requests and debug info
    --fetch-timeout <ms>      External fetch timeout for renderer HTTP requests (default 15000)
    -s, --silent              Less verbose output
    -l|--log_file <file>      output log file (defaults to standard out)
    -f|--log_format <format>  define the log format: https://github.com/expressjs/morgan#morganformat-options
    --ignore-missing-files    Continue startup even if configured mbtiles/pmtiles files are missing
    --metrics                 Enable Prometheus metrics endpoint (env: TILESERVER_GL_METRICS)
    -v, --version             output the version number
    -h, --help                display help for command
```

A bare positional argument is treated as the input file: `tileserver-gl zurich.mbtiles`.

## Startup behaviour

The config file is looked up first (`--config`, default `config.json` in the working directory). Only if it is
missing or empty does the server fall back to a single input file:

1. `--file`, then the deprecated `--mbtiles`.
2. Otherwise the first `*.mbtiles` / `*.pmtiles` file found in the working directory.
3. Otherwise a sample file (Zurich area) is downloaded from GitHub.

In that fallback mode a config is generated in memory. If the tile set is in OpenMapTiles format
(`format: pbf` and a name containing `openmaptiles`), every style bundled in `tileserver-gl-styles` is served
against it; otherwise only the raw data endpoints are exposed. Run with `--verbose` to print the generated config.

`--file` accepts remote PMTiles (`https://…​.pmtiles`, `s3://…`, `pmtiles://…`). MBTiles must be local —
a remote MBTiles URL is rejected at startup.

## Environment variables

| Variable                       | Effect                                                                       |
|--------------------------------|------------------------------------------------------------------------------|
| `PORT`                         | Overrides `--port`.                                                          |
| `BIND`                         | Overrides `--bind`.                                                          |
| `PUBLIC_URL`                   | Public base URL for generated links (TileJSON/`styles.json`/WMTS), same as `--public_url` (the flag wins). Setting it also silences the host-header security warning. |
| `TILESERVER_GL_ALLOWED_HOSTS`  | Comma-separated host allowlist, or `*`. Overridden by `options.allowedHosts`. |
| `TILESERVER_GL_API_KEYS`       | Comma-separated static API keys. Setting this (or the token secret) makes every endpoint except `/health` require `?key=`. |
| `TILESERVER_GL_TOKEN_SECRET`   | Shared secret enabling expiring HMAC tokens as keys (see below).              |
| `TILESERVER_GL_TOKEN_MAX_TTL`  | Max seconds a token's expiry may be in the future (default `604800`, 7 days). A token whose expiry exceeds now + this is rejected, capping mis-issued far-future tokens. |
| `TILESERVER_GL_ALLOWED_ORIGINS`| Comma-separated `Origin` allowlist. Checked in addition to the key, and used to restrict CORS instead of `*`. Not to be confused with `…_ALLOWED_HOSTS`, which governs URL generation. |
| `TILESERVER_GL_METRICS`        | `true` enables the Prometheus endpoint, same as `--metrics`.                  |
| `TILESERVER_GL_METRICS_ZOOM`   | `true` adds a per-zoom label to rendered-tile metrics (full image only).       |
| `METRICS_PORT`                 | Port for the metrics server (default `9090`, bound to `127.0.0.1`).           |
| `UV_THREADPOOL_SIZE`           | libuv threadpool size. Defaults to `max(4, cpus × 1.5)`.                      |
| `NODE_ENV`                     | `production` switches the default morgan log format to `tiny` (`dev` otherwise). |
| `CHOKIDAR_USEPOLLING`, `CHOKIDAR_INTERVAL` | Watcher tuning for `serveAllStyles` (set in the Docker images). |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` | Credentials for `s3://` / `s3+https://` PMTiles data sources (standard AWS SDK chain). |
| `AWS_REGION`                   | Default region for S3 data sources (default `us-east-1`); a source's `s3Region` overrides it. |
| `AWS_PROFILE`                  | Named profile from a mounted `~/.aws` (SDK chain); a source's `s3Profile` overrides per source. |
| `TILESERVER_GL_S3_MAX_SOCKETS` | Max concurrent connections in the S3 client pool (default `256`; the AWS SDK's own default is 50). Raise for more parallel tile range-GETs under load. |
| `TILESERVER_GL_S3_KEEP_ALIVE`  | Keep S3 sockets alive between requests (default `true`).                       |
| `TILESERVER_GL_S3_CONNECTION_TIMEOUT_MS` | S3 socket-connect timeout in ms (default `5000`; `0` disables).      |
| `TILESERVER_GL_S3_REQUEST_TIMEOUT_MS` | Deadline in ms for each S3 range read, covering connect, retries and the response body (default `5000`; `0` disables). A stalled read fails instead of holding the tile request open. |

Any string in `config.json` can also reference the environment as `${VAR}` or `${VAR:-default}` (see
[Configuration › Environment variable substitution](3.CONFIG.md#environment-variable-substitution)). Those
variable names are chosen by the config author — e.g. this project's S3 config uses `PMTILES_URL` for the
tileset URL and `TILE_CACHE_CONTROL` for the tile `Cache-Control` — so one baked image retargets per
deployment without a rebuild.

## Default preview style and configuration

- If no configuration file is specified, a default preview style (compatible with OpenMapTiles) is used.
- If no data file is specified (and none is found in the current working directory), a sample file is
  downloaded (showing the Zurich area).

## HTTP endpoints

`{id}` is the key used in the `styles` / `data` object of the config file. `{tileSize}` is optional and may
only be `256` or `512`. `@{scale}x` is optional and limited by `maxScaleFactor`.

### Styles and vector data

| Endpoint                                       | Description                                              |
|------------------------------------------------|----------------------------------------------------------|
| `GET /styles.json`                              | List of served styles with their style.json URLs.        |
| `GET /styles/{id}/style.json`                   | Style JSON with sources/sprites/glyphs rewritten to this server. |
| `GET /styles/{id}/`                             | MapLibre viewer for the style.                           |
| `GET /styles/{id}/wmts.xml`                     | WMTS capabilities (only for styles that are rendered).   |
| `GET /styles/{id}/sprite[/{spriteId}][@{n}x].{png,json}` | Sprite sheet; `spriteId` defaults to `default`, `n` up to 3. |
| `GET /fonts/{fontstack}/{range}.pbf`            | Glyph range, e.g. `/fonts/Open Sans Regular/0-255.pbf`. Comma-separated font stacks are merged. |
| `GET /fonts.json`                               | List of available fonts.                                 |
| `GET /data.json`                                | TileJSON array for every data source.                    |
| `GET /data/{id}.json`                           | TileJSON for one data source.                            |
| `GET /data/{id}/{z}/{x}/{y}.{format}`           | Raw tile. `format` must match the tile set (`pbf`, `png`, `jpg`, `webp`); `pbf` sources also answer `geojson`. |
| `GET /data/{id}/`                               | Data viewer (MapLibre for vector, Leaflet for raster).   |
| `GET /data/preview/{id}/`                       | 3-D terrain preview for sources with an `encoding` set (full image only). |
| `GET /files/…`                                  | Static files from `paths.files`.                         |

`pbfAlias` in the config lets `.pbf` tiles be requested under a different extension; the `.pbf` URL keeps working.

For vector sources a missing tile answers `204 No Content` and for raster sources `404 Not Found`; the
`sparse` option, or a `sparse` entry in the archive's metadata, flips that (see [CONFIGURATION.md](3.CONFIG.md)).

### Rendered raster tiles (full image only)

| Endpoint                                                       | Description                          |
|-----------------------------------------------------------------|--------------------------------------|
| `GET /rendered.json`, `GET /{tileSize}/rendered.json`           | TileJSON array for rendered styles.  |
| `GET /index.json`, `GET /{tileSize}/index.json`                 | Rendered + data TileJSONs combined.  |
| `GET /styles/{id}.json`, `GET /styles/{tileSize}/{id}.json`     | TileJSON for one rendered style.     |
| `GET /styles/{id}/{z}/{x}/{y}[@{n}x].{format}`                  | Rendered tile (`png`, `jpg`, `webp`).|
| `GET /styles/{id}/{tileSize}/{z}/{x}/{y}[@{n}x].{format}`       | Rendered tile at 256 or 512 px.      |

### Static maps (full image only)

Enabled unless `serveStaticMaps` is `false`. All four forms take `{width}x{height}` and an optional
`@{n}x` scale factor:

```
GET /styles/{id}/static/{lon},{lat},{zoom}[@{bearing}[,{pitch}]]/{width}x{height}[@{n}x].{format}
GET /styles/{id}/static/{minx},{miny},{maxx},{maxy}/{width}x{height}[@{n}x].{format}
GET /styles/{id}/static/auto/{width}x{height}[@{n}x].{format}
GET /styles/{id}/static/raw/…                     (same three forms, coordinates in EPSG:3857 meters)
```

`auto` derives center and zoom from the overlays passed in the query string. Supported query parameters:

* `path` — repeatable. `enc:{polyline}` or `lon,lat|lon,lat|…`, optionally prefixed with
  `fill:`, `stroke:`, `width:`, `border:`, `borderwidth:` options separated by `|`.
* `marker` — repeatable. `lon,lat|{icon}` with optional `scale:{factor}` and `offset:{x}[,{y}]` options.
  Icons come from `paths.icons`; remote (http(s)) and inline (data URI) icons require
  `allowRemoteMarkerIcons` / `allowInlineMarkerImages`.
* `latlng=1` — coordinates in paths/markers are given as `lat,lon` instead of `lon,lat`.
* `padding` — fraction of the image kept free around the content for the bbox/`auto` forms.
* `maxzoom` — caps the zoom computed for the bbox/`auto` forms.
* `fill`, `stroke`, `width`, `border`, `borderwidth`, `linecap`, `linejoin` — defaults for all paths.

The same routes accept `POST` with a JSON body (max 5 MB) whose keys are merged over the query string —
useful when a long `path` would exceed URL length limits. `POST` to a *tile* route returns `405`.

### Elevation (full image only)

Available for data sources configured with `encoding: "mapbox"` or `encoding: "terrarium"`.

```
GET  /data/{id}/elevation/{z}/{x}/{y}          # integer x/y: tile center; float x/y: lon/lat
POST /data/{id}/elevation                      # {"points": [{"lon": …, "lat": …, "z": …}, …]}
```

`GET` answers `204` when the source has no value at that location, `404` when the tile is out of bounds.
`POST` returns an array of elevations (`null` where there is no data) in the order of the input points.

### Operations

| Endpoint       | Description                                                                    |
|----------------|--------------------------------------------------------------------------------|
| `GET /`        | Front page listing styles and data (see `frontPage`).                          |
| `GET /health`  | `200 OK` once startup finished, `503 Starting` before that. Used by the Docker `HEALTHCHECK`. |
| `GET /metrics` | Prometheus exposition — **on the separate metrics port**, not the main port.    |

## Caching

Successful responses carry a `Cache-Control` header so browsers and CDNs stop re-fetching
content that has not changed. Tiles get a day of freshness plus a week of
`stale-while-revalidate`; glyphs, sprites, `style.json` and the TileJSON/catalog endpoints get
an hour (their URLs carry no version, so none of them is `immutable`); viewer HTML is `no-cache` and `/health` is `no-store`.
Errors — including the `403` from the key gate — never carry one.

This is what makes a CDN in front of the server effective: without an explicit `Cache-Control`
most CDNs will not store a response at all. Revalidation alone does not protect the origin,
since a `304` runs the same work as a `200` before the ETag is compared.

The per-category values are configurable — see `cacheControl` in [3.CONFIG.md](3.CONFIG.md).

## API keys and expiring tokens

Authentication is off by default. Setting `TILESERVER_GL_API_KEYS` and/or `TILESERVER_GL_TOKEN_SECRET`
mounts a gate in front of every endpoint except `/health` (probes and the Docker `HEALTHCHECK` stay
credential-free). The credential travels as `?key=` on the **query string**; since the server already
propagates `key` into every URL it generates — TileJSON `tiles`, `style.json`, sprites, glyphs, viewer
links — a client only supplies it once with the style URL and the whole session stays authorized.

`/health` and the static viewer chrome under `public/resources` (the MapLibre/Leaflet bundles, webfonts,
images, `favicon.ico`, `index.css`) are exempt, because CSS `url()`, `<img>` and the browser's automatic
favicon request cannot carry `?key=` and gating them would break the built-in viewer. Everything that
carries map data — tiles, `style.json`, glyph `.pbf`s, sprites, and the `/styles.json` · `/data.json`
catalog — stays protected. The exempt set is enumerated from disk, so it is exactly those files and never
a data route.

Two credential forms are accepted interchangeably:

* **Static keys** — any value listed in `TILESERVER_GL_API_KEYS`. Simple, but a leaked key works until
  rotated.
* **Expiring tokens** — `key=<unix-expiry>.<signature>` where the signature is
  `hmac_sha256(<unix-expiry as string>, TILESERVER_GL_TOKEN_SECRET)` hex-encoded. Stateless: nothing to
  distribute or revoke, leaked tokens die at their expiry. An expiry further ahead than
  `TILESERVER_GL_TOKEN_MAX_TTL` is rejected, so a mis-issued far-future token can't become permanent.
  Tokens grant all-or-nothing access — there is no per-style or per-path scoping. Issue them from the
  backend that embeds the map, e.g. in PHP:

  ```php
  $expiry = time() + 3600;
  $key = $expiry . '.' . hash_hmac('sha256', (string) $expiry, env('TILES_TOKEN_SECRET'));
  $styleUrl = "https://tiles.example.com/styles/basic-v2/style.json?key={$key}";
  ```

`TILESERVER_GL_ALLOWED_ORIGINS` optionally adds hotlink deterrence on top, and narrows CORS to the listed
origins instead of `*`. When set, the requesting site is taken from the `Origin` header when present
(browsers send it on cross-origin fetch/XHR and it cannot be forged from a page) and otherwise from the
`Referer` header's origin — which covers the main hotlink vector, since `<img>`, `<link>`, CSS `url()`
and raster-tile loads send no `Origin` but do send `Referer`. A request whose derived origin is not on
the list is rejected with 403 even with a valid key.

This **deters, it does not prevent**, and it is not authentication:

* Same-origin requests (the server's own viewer loading its style, tiles, sprites and glyphs) always
  pass — the server's own origin is allowed regardless of the list.
* A request carrying neither header (curl, server-side fetch, or a page served with
  `Referrer-Policy: no-referrer`) passes the origin check — only the key is enforced. A determined
  embedder who strips the referrer therefore bypasses it.
* Keys travel in URLs and are readable from your own page's style URL, so treat the origin list as a way
  to stop casual `<img src>`-style embedding by other sites, not as a trust boundary. For a real boundary
  use short-lived tokens (above) and keep the TTL short.

Comparisons are constant-time. Keys appear in query strings, so they show up in browser history and in the
logs of any proxy in front of the server (see [Deployment](4.DEPLOYMENT.md) for an nginx log format without
them); prefer short-lived tokens where that matters. The server's own request log redacts them (see Logging).

## Prometheus metrics

Start with `--metrics` (or `TILESERVER_GL_METRICS=true`). The metrics server listens on `127.0.0.1:9090`
by default (`METRICS_PORT`); it is deliberately not exposed on the main port and binds to loopback only,
so scraping from another host requires a sidecar or an SSH/reverse-proxy hop. Failure to bind is logged
and does not stop the tile server.

Besides the default Node.js process metrics it exports:

| Metric                                        | Type      | Labels                        |
|-----------------------------------------------|-----------|-------------------------------|
| `tileserver_http_requests_total`              | counter   | `method`, `route`, `status_code` |
| `tileserver_http_request_duration_seconds`    | histogram | `method`, `route`, `status_code` |
| `tileserver_tiles_served_total`               | counter   | `type`, `name`                |
| `tileserver_tile_render_duration_seconds`     | histogram | `name`, `zoom`                |
| `tileserver_tile_errors_total`                | counter   | `type`, `name`                |
| `tileserver_render_pool_size`                 | gauge     | `name`                        |
| `tileserver_render_pool_active`               | gauge     | `name`                        |
| `tileserver_render_pool_waiting`              | gauge     | `name`                        |

## Reloading the configuration

The configuration file can be reloaded without restarting the process by sending `SIGHUP`. The server shuts
down its listeners, closes the tile sources, clears the PMTiles cache and starts again from the config file;
reloads requested while one is running are queued.

- `docker kill -s HUP tileserver-gl` for a container.
- `docker compose kill -s HUP tileserver-gl` for a compose service.

With `serveAllStyles` enabled, styles added to or removed from `paths.styles` are picked up automatically —
no signal needed.

## Docker and `--port`

When running in a container, `--port` makes the container look unhealthy, because the bundled healthcheck
always probes port 8080 inside the container. Use Docker's port mapping instead and keep the internal
port at 8080.

## Logging

Request logging uses [morgan](https://github.com/expressjs/morgan#morganformat-options); the format is
`--log_format`, defaulting to `tiny` under `NODE_ENV=production` and `dev` otherwise. `--log_file` appends
to a file instead of stdout. `--silent` suppresses `200`/`304` lines. `--verbose` (levels 1–3) controls the
application's own diagnostics, independent of request logging.

The value of every `key` query parameter is logged as `[REDACTED]`, in the request URL and in the `Referer`
(which the `combined` format logs), however the parameter name is percent-encoded. Viewer pages are served
with `Referrer-Policy: strict-origin`, so the requests they make send only the origin as their `Referer`.
