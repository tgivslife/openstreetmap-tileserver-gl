# Configuration

The configuration file defines the behavior of the application. It's a regular JSON file.

Example:

```json
{
  "options": {
    "paths": {
      "root": "",
      "fonts": "fonts",
      "sprites": "sprites",
      "icons": "icons",
      "styles": "styles",
      "mbtiles": "data",
      "pmtiles": "data",
      "files": "files"
    },
    "domains": [
      "localhost:8080",
      "127.0.0.1:8080"
    ],
    "allowedHosts": "tiles.example.com",
    "formatOptions": {
      "jpeg": {
        "quality": 80
      },
      "webp": {
        "quality": 90
      }
    },
    "maxScaleFactor": 3,
    "maxSize": 2048,
    "pbfAlias": "pbf",
    "cacheControl": {
      "tile": "public, max-age=86400, stale-while-revalidate=604800"
    },
    "serveAllFonts": false,
    "serveAllStyles": false,
    "serveStaticMaps": true,
    "allowRemoteMarkerIcons": true,
    "allowInlineMarkerImages": true,
    "staticAttributionText": "© OpenMapTiles  © OpenStreetMaps",
    "tileMargin": 0
  },
  "styles": {
    "basic": {
      "style": "basic.json",
      "tilejson": {
        "type": "overlay",
        "bounds": [8.44806, 47.32023, 8.62537, 47.43468]
      }
    },
    "hybrid": {
      "style": "satellite-hybrid.json",
      "serve_rendered": false,
      "tilejson": {
        "format": "webp"
      }
    }
  },
  "data": {
    "zurich-vector": {
      "mbtiles": "zurich.mbtiles"
    }
  }
}
```

All paths in the config are resolved relative to the directory holding the config file (or the working
directory when the config is generated automatically). A configured path that does not exist aborts startup.

## Environment variable substitution

Any string value in the config may reference an environment variable as `${VAR}` or `${VAR:-default}`. The
substitution runs after the JSON is parsed (so an env value can never break the JSON), over every string in
the file. This lets a single committed — or image-baked — `config.json` carry per-deployment values (an S3
URL, a region, an endpoint) without editing the file.

- `${VAR}` — replaced with the value of `VAR`. The variable is required: if it is unset or empty, startup
  aborts with `ERROR: Config file references environment variable(s) that are not set: VAR`.
- `${VAR:-default}` — replaced with `VAR`, or with `default` when `VAR` is unset **or empty** (shell `:-`
  semantics).

Only `${...}` is expanded; the single-brace tokens used elsewhere (glyph `{fontstack}/{range}`, tile
`{z}/{x}/{y}`) are untouched, and substituted text is not re-scanned (no nested expansion).

Example — one image, a different tileset per environment:

```json
  "data": {
    "planet": {
      "pmtiles": "${PMTILES_URL}",
      "s3Region": "${AWS_REGION:-us-east-1}"
    }
  }
```

```bash
# set at runtime (compose env, k8s env/Secret) — no rebuild. PMTILES_URL is required (no default), so a
# deployment that forgets it fails at startup naming the variable; AWS_REGION falls back to us-east-1:
PMTILES_URL=s3://my-bucket/planet.pmtiles
```

Leave out a default when there is no value that is right for every deployment. A default pointing at a
development host (e.g. `s3+http://minio:9000/...`) turns a missing variable into a misleading credentials or
DNS error against that host.

## Options

``paths``
------------------------

Defines where to look for the different types of input data.
The value of `root` is used as prefix for all data types.

`icons` defaults to the built-in `public/resources/images` (marker icons for static maps) and `files`
defaults to `public/files` (served under `/files/`).

``domains``
------------------------

You can use this to optionally specify on what domains the rendered tiles are accessible.
This can be used for basic load-balancing or to bypass browser's limit for the number of connections per domain.

``allowedHosts``
------------------------

Allowlist of hosts that may appear in the `Host` / `X-Forwarded-Host` header when the server builds absolute
URLs (TileJSON `tiles`, `styles.json`, WMTS). Either `"*"` or a comma-separated string / array of hostnames;
ports are ignored and matching is case-insensitive.

When a request arrives with a host that is not on the list, the server falls back to **relative** URLs instead
of echoing the attacker-supplied host — this is the host-header-poisoning mitigation. The default `"*"` allows
any host and logs a security warning at startup unless `--public_url` is set.

Precedence: `options.allowedHosts` > `TILESERVER_GL_ALLOWED_HOSTS` env > `"*"`.

``frontPage``
------------------------

Path to the html (relative to ``root`` path) to use as a front page.

Use ``true`` (or nothing) to serve the default TileServer GL front page with list of styles and data.
Use ``false`` to disable the front page altogether (404).

``formatOptions``
------------------------

You can use this to specify options for the generation of images in the supported file formats.

For WebP, the only supported option is ``quality`` [0-100].
For JPEG, the only supported options are ``quality`` [0-100] and ``progressive`` [true, false].

For PNG, the full set of options `exposed by the sharp library <https://sharp.pixelplumbing.com/api-output#png>`_ is available, except ``force`` and
``colours`` (use ``colors``).
If not set, their values are the defaults from ``sharp``.

For example:

```
    "formatOptions": {
    "png": {
      "palette": true,
      "colors": 4
    }
  }
```

The older ``formatQuality`` option (a plain `format -> quality` map) still works for JPEG and WebP but is
deprecated; it is only consulted when ``formatOptions`` does not provide a quality and logs a warning.

``maxScaleFactor``
------------------------

Maximum scale factor to allow in raster tile and static maps requests (e.g. ``@3x`` suffix).
Also see ``maxSize`` below.

Default value is ``3``, maximum ``9``.

``maxSize``
------------------------

Maximum image side length to be allowed to be rendered (including scale factor).
Be careful when changing this value since there are hardware limits that need to be considered.
Default is ``2048``.

``maxStaticMarkers``, ``maxStaticPaths``, ``maxStaticPathPoints``
------------------------

Most markers, paths and path coordinates (summed over all paths, encoded or not) a single static map request may draw,
whether sent in the query string or a POST body. A request over any of them is answered ``400``, before any of its
overlay is parsed or drawn. At the defaults, the largest overlay a request can draw (100 markers and 20,000 path
coordinates on a 2048 px image) takes about 0.2 s and 30 MB; raising them raises that cost roughly in proportion,
markers most of all, since each one loads and decodes its icon.

Defaults are ``100``, ``100`` and ``20000``.

``tileMargin``
------------------------

Additional image side length added during tile rendering that is cropped from the delivered tile. This is useful for resolving the issue with cropped labels,
but it does come with a performance degradation, because additional, adjacent vector tiles need to be loaded to generate a single tile.

Default is ``0`` to disable this processing.

``minRendererPoolSizes``
------------------------

Minimum amount of raster tile renderers per scale factor.
The value is an array: the first element is the minimum amount of renderers for scale factor one, the second for scale factor two and so on.
If the array has less elements than ``maxScaleFactor``, then the last element is used for all remaining scale factors as well.
Selecting renderer pool sizes is a trade-off between memory use and speed.
A reasonable value will depend on your hardware and your amount of styles and scale factors.
If you have plenty of memory, you'll want to set this equal to ``maxRendererPoolSizes`` to avoid increased latency due to renderer destruction and recreation.
If you need to conserve memory, you'll want something lower than ``maxRendererPoolSizes``, possibly allocating more renderers to scale factors that are more
common.

Default is ``[8, 4, 2]``.

``maxRendererPoolSizes``
------------------------

Maximum amount of raster tile renderers per scale factor.
The value and considerations are similar to ``minRendererPoolSizes`` above.
If you have plenty of memory, try setting these equal to or slightly above your processor count, e.g. if you have four processors, try a value of ``[6]``.
If you need to conserve memory, try lower values for scale factors that are less common.

Default is ``[16, 8, 4]``.

``pbfAlias``
------------------------

Some CDNs did not handle .pbf extension as a static file correctly.
The default URLs (with .pbf) are always available, but an alternative can be set.
An example extension suffix would be ".pbf.pict".

``cacheControl``
------------------------

Controls the ``Cache-Control`` header sent with successful responses. Errors (404, and the
403 from the API-key gate) never carry one. Responses are grouped into five categories:

+--------------+----------------------------------------------+-------------------------------------------------------+
| Category     | Applies to                                   | Default                                               |
+==============+==============================================+=======================================================+
| ``tile``     | vector + rendered tiles, static maps,        | ``public, max-age=86400, stale-while-revalidate=604800``|
|              | elevation lookups                            |                                                       |
+--------------+----------------------------------------------+-------------------------------------------------------+
| ``asset``    | glyph ranges, sprite sheets                  | ``public, max-age=3600``                              |
+--------------+----------------------------------------------+-------------------------------------------------------+
| ``metadata`` | ``style.json``, TileJSON, ``/styles.json``,  | ``public, max-age=3600``                              |
|              | ``/data.json``, ``/index.json``,             |                                                       |
|              | ``/fonts.json``                              |                                                       |
+--------------+----------------------------------------------+-------------------------------------------------------+
| ``static``   | files under ``public/resources`` and         | ``public, max-age=86400``                             |
|              | ``paths.files``                              |                                                       |
+--------------+----------------------------------------------+-------------------------------------------------------+
| ``html``     | viewer pages, WMTS XML                       | ``no-cache``                                          |
+--------------+----------------------------------------------+-------------------------------------------------------+

``/health`` is always ``no-store`` so probes never see a stored answer.

The defaults assume tiles change only when you rebuild the archives. If you rebuild more
often, shorten ``tile``; the ``stale-while-revalidate`` window lets a CDN keep serving the
old tile while it fetches the new one, so shortening ``max-age`` costs little.

Override individual categories, or set a category to ``false`` to send no header for it:

.. code-block:: javascript

    "options": {
      "cacheControl": {
        "tile": "public, max-age=3600",
        "html": false
      }
    }

Set ``"cacheControl": false`` to disable the headers entirely and restore the previous
behaviour of sending none.

Note that ``public`` lets shared caches store the response. Since the API key travels in
the query string, a CDN keys its cache per key — with static keys that is what you want,
but with per-user expiring tokens every user gets a separate cache entry and the hit rate
collapses. If you use tokens, consider serving ``style.json`` and tiles through a CDN path
that strips the key, or accept the lower hit rate.

``serveAllFonts``
------------------------

If this option is enabled, all the fonts from the ``paths.fonts`` will be served.
Otherwise, only the fonts referenced by available styles will be served.

``serveAllStyles``
------------------------

If this option is enabled, all the styles from the ``paths.styles`` will be served. (No recursion, only ``.json`` files
are used.)
The process will also watch for changes in this directory and remove/add more styles dynamically.
It is recommended to also use the ``serveAllFonts`` option when using this option.

``serveStaticMaps``
------------------------

If this option is enabled, all the static map endpoints will be served.

Default is ``true``.

``sparse``
------------------------

Controls the response for a tile that is not present in the tile set:

* ``true`` -- respond ``404``, which lets clients overzoom from the parent tile.
* ``false`` -- respond ``204 No Content``, an explicitly empty tile.

The same setting decides what the renderer does with a missing tile: ``true`` overzooms from the parent
tile, ``false`` draws an empty tile. For a rendered style it applies to each data source the style uses.

Resolved from the first of these that is set, highest priority first:

1. ``sparse`` on the data source (see [Data](#data))
2. ``sparse`` here in the top-level ``options``
3. ``sparse`` in the archive's own metadata (the MBTiles ``metadata`` table, or the PMTiles metadata JSON)
4. the tile format -- ``false`` for vector (``pbf``) sources, ``true`` for raster sources

Config outranks archive metadata, so a source that declares the wrong value for your deployment can be
corrected without rewriting the file. MBTiles metadata values are text: ``"true"``/``"false"`` and
``"1"``/``"0"`` are understood, anything else is ignored rather than guessed at. The data source's TileJSON
(``/data/{id}.json``) reports the resolved value.

``watermark``
------------------------

Optional string to be rendered into the raster tiles and static maps as watermark (bottom-left corner).

Not used by default.

``staticAttributionText``
------------------------

Optional string to be rendered in the static images endpoint. Text will be rendered in the bottom-right corner,
and styled similar to attribution on web-based maps (text only, links not supported).

Not used by default.

``allowRemoteMarkerIcons``
------------------------

Allows the rendering of marker icons fetched via http(s) hyperlinks.
For security reasons only allow this if you can control the origins from where the markers are fetched!
Default is to disallow fetching of icons from remote sources.

``allowInlineMarkerImages``
------------------------

Allows the rendering of inline marker icons or base64 urls.
For security reasons only allow this if you can control the origins from where the markers are fetched!
Not used by default.

``leafletRetina``
------------------------

Set to ``true`` to make the bundled Leaflet viewer request retina (``@2x``) tiles.

Not used by default.

``dataDecorator``
------------------------

Path (relative to ``root``) of an ES module whose default export post-processes served data. It is called as
``fn(id, 'tilejson', tileJSON)`` when a TileJSON is assembled and as ``fn(id, 'data', buffer, z, x, y)`` for
each vector tile, and must return the replacement value, modified or not - returning nothing discards the data.

- ``'tilejson'`` is passed the TileJSON served at ``/data/{id}.json``, and each local (MBTiles or PMTiles) source
  a rendered style pulls in; ``id`` is the data source id or the style's source name.
- ``'data'`` is passed the un-gzipped vector tile ``Buffer``, both for ``/data/{id}/{z}/{x}/{y}.pbf`` and for the
  tiles fed to the renderer. Raster tiles are never passed through it.
- The function may be ``async`` or return a promise; the result is awaited. It runs once per tile for ``'data'``,
  so keep it fast or cache inside the module.

Loading errors are logged and the server starts without a decorator, so check the startup output if it does
not appear to run.

## Styles

``styles``
------------------------

Each item in this object defines one style (map). It can have the following options:

* ``style`` -- name of the style json file, or an ``http(s)`` URL to one [required]
* ``serve_rendered`` -- whether to render the raster tiles for this style or not (forced off in the light build)
* ``serve_data`` -- whether to allow access to the original tiles, sprites and required glyphs
* ``tilejson`` -- properties to add to the TileJSON created for the raster data

    * ``format`` and ``bounds`` can be especially useful

* ``mapping`` -- rename the data ids a style refers to, ``{ "<id in style>": "<id in config data>" }``

``mapping`` is what lets one style file be reused against different tile sets. A style containing
``"url": "mbtiles://{planet}"`` combined with

```json
  "styles": {
    "basic": {
      "style": "basic/style.json",
      "mapping": { "planet": "romania" }
    }
  },
  "data": {
    "romania": { "mbtiles": "romania-latest.mbtiles" }
  }
```

resolves the style's ``planet`` source to the ``romania`` data source, without editing the style file.

## Data

``data``
------------------------

Each item specifies one data source which should be made accessible by the server. It has to have one of the following options:

* ``mbtiles`` -- name of the mbtiles file
* ``pmtiles`` -- name of the pmtiles file or url.

For example:

```json
  "data": {
    "source1": {
      "mbtiles": "source1.mbtiles"
    },
    "source2": {
      "pmtiles": "source2.pmtiles"
    },
    "source3": {
      "pmtiles": "https://foo.lan/source3.pmtiles"
    }
  }
```

The data source does not need to be specified here unless you explicitly want to serve the raw data.

Additional per-source options:

* ``tilejson`` -- properties merged into the generated TileJSON
* ``sparse`` -- overrides the global ``sparse`` option for this source
* ``encoding`` -- ``mapbox`` or ``terrarium`` for terrain sources (see below)

### Remote and S3-hosted PMTiles

PMTiles sources may be served straight from HTTP or from S3-compatible object storage
(`s3://bucket/key`, or `s3+https://endpoint/bucket/key` for non-AWS providers). Credentials are resolved by
the AWS SDK (environment, `~/.aws/credentials`, instance role), and the following per-source options apply:

* ``s3Profile`` -- credential profile name
* ``s3Region`` -- region override (otherwise `AWS_REGION`, default `us-east-1`)
* ``s3UrlFormat`` -- ``aws`` or ``custom`` to override endpoint auto-detection
* ``requestPayer`` -- ``true`` for requester-pays buckets

```json
  "data": {
    "planet": {
      "pmtiles": "s3://my-bucket/tiles/planet.pmtiles",
      "s3Region": "eu-central-1",
      "s3Profile": "tiles"
    }
  }
```

MBTiles are SQLite files and must be local — remote MBTiles URLs are rejected.

### Serving Terrain Tiles

If you serve terrain tiles, it is possible to configure an ``encoding`` with ``mapbox`` or ``terrarium`` to enable a terrain preview mode and the ``elevation`` api for the ``data`` endpoint.

For example:

```json
  "data": {
    "terrain1": {
      "mbtiles": "terrain1.mbtiles",
      "encoding": "mapbox"
    },
    "terrain2": {
      "pmtiles": "terrain2.pmtiles",
      "encoding": "terrarium"
    }
  }
```

The terrain preview and the elevation endpoints need the renderer, so they are unavailable in the light build.

## Referencing local files from style JSON

You can link various data sources from the style JSON (for example even remote TileJSONs).

### MBTiles

To specify that you want to use local mbtiles, use to following syntax: ``mbtiles://source1.mbtiles``.
TileServer-GL will try to find the file ``source1.mbtiles`` in ``root`` + ``mbtiles`` path.

For example:

```json
  "sources": {
    "source1": {
      "url": "mbtiles://source1.mbtiles",
      "type": "vector"
    }
  }
```

Alternatively, you can use ``mbtiles://{source1}`` to reference existing data object from the config.
In this case, the server will look into the ``config.json`` to determine what file to use by data id.
For the config above, this is equivalent to ``mbtiles://source1.mbtiles``.

### PMTiles

To specify that you want to use local pmtiles, use to following syntax: ``pmtiles://source2.pmtiles``.
TileServer-GL will try to find the file ``source2.pmtiles`` in ``root`` + ``pmtiles`` path.

To specify that you want to use a url based pmtiles, use to following syntax: ``pmtiles://https://foo.lan/source3.pmtiles``.

For example:

```json
  "sources": {
    "source2": {
      "url": "pmtiles://source2.pmtiles",
      "type": "vector"
    },
    "source3": {
      "url": "pmtiles://https://foo.lan/source3.pmtiles",
      "type": "vector"
    }
  }
```

Alternatively, you can use ``pmtiles://{source2}`` to reference existing data object from the config.
In this case, the server will look into the ``config.json`` to determine what file to use by data id.
For the config above, this is equivalent to ``pmtiles://source2.mbtiles``.

A style that references a file which is not listed under ``data`` gets that source added automatically.
Missing files abort startup unless the server is run with ``--ignore-missing-files``, which skips the
affected sources (their requests then return 404) and keeps the rest of the configuration serving.

### Sprites

If your style requires any sprites, make sure the style JSON contains proper path in the ``sprite`` property.

It can be a local path (e.g. ``my-style/sprite``) or remote http(s) location (e.g. ``https://mycdn.com/my-style/sprite``). 
Several possible extension are added to this path, so the following files should be present:

* ``sprite.json``
* ``sprite.png``
* ``sprite@2x.json``
* ``sprite@2x.png``

You can also use the following placeholders in the sprite path for easier use:

* ``{style}`` -- gets replaced with the name of the style file (``xxx.json``)
* ``{styleJsonFolder}`` -- gets replaced with the path to the style file

### Fonts (glyphs)

Similarly to the sprites, the style JSON also needs to contain proper paths to the font glyphs (in the ``glyphs`` property) and can be both local and remote.

It should contain the following placeholders:

* ``{fontstack}`` -- name of the font and variant
* ``{range}`` -- range of the glyphs

For example ``"glyphs": "{fontstack}/{range}.pbf"`` will instruct TileServer-GL to look for the files such as ``fonts/Open Sans/0-255.pbf`` (``fonts`` come from the ``paths`` property of the ``config.json`` example above).
